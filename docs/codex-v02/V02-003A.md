## 行为与兼容

新工作簿含 veryHidden `_个人字段基线`，每个 paperId 对应三个人字段；`_身份!C1:D1` 保存格式 `scientific-reading-user-fields-v1` 和基线集合 SHA256。身份表原有前两列保持不变。基线随临时 XLSX 保存、fsync、os.replace 一起发布，不引入数据库版本字段，不使用分类 revision 或 mtime。

逐字段采用 B/E/D：E=B 保留 D；E=D 保留共同值；D=B 接受 E；其余为冲突。None/空单元格按空字符串比较，清空是编辑。基线值以字符串保存，校验格式、表头、paperId 集合、重复记录、数据类型和内容摘要。超出 Excel 32767 字符的 DB 个人字段阻止发布，避免截断后形成错误基线。SHA256 用于发现损坏，不是防恶意伪造的签名。

无基线且无格式标记的历史工作簿，仅当 Excel 三字段与 DB 相同才可安全 refresh 建立基线；存在差异则 `baseline_missing_difference`，不判断哪边较新。已带标记但表/摘要损坏，或重复/缺失记录，整批 pending，不降级导入。直接 import 不发布新基线，只有成功 refresh 才发布。

身份或内容冲突时：整批 `updated=0`，不替换原工作簿，DB 个人字段不变；允许更新既有 library_meta 诊断项。身份错误继续使用 `xlsx_identity_conflict`；内容/基线错误使用 `xlsx_user_fields_conflict`。`conflict_details` 和 `xlsx_conflicts` 给出 paperId/字段/原因（结构损坏为整体原因），不复制笔记内容到日志。`xlsx_pending=1`、`xlsx_error` 和原有 worker waiting_user 路径保持一致。提示先备份并核对两端；可在核对后使 Excel 与 DB 一致，再 refresh，不自动选胜者。

SQLite 使用 `BEGIN IMMEDIATE`，在写锁取得后重读 D，完成全批判断后才 UPDATE；其他写连接必须先提交或等本批结束。仅实际变化的行计入 updated。导入已提交而文件替换失败时，B 仍随旧文件保留；重试 E=D 幂等。若重试前 DB 又改成第三个值，会重新报告冲突。工作簿占用、权限/替换失败和身份保护继续保留。
